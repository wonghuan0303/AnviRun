# 通用构建任务平台：分阶段实施计划

## 1. 执行原则

本计划面向多个智能体协作，但每个任务必须在明确依赖完成后开始。不同智能体不得同时修改同一模块的核心文件。每项任务提交前必须运行对应格式化、静态检查和测试，并在交付说明中列出：变更范围、数据库/API 变化、测试结果、遗留风险。

实施目标是从空仓库构建新系统；`C:\workspace\work\client-package-service` 与 `C:\workspace\work\client-package-web` 仅作参考，不复制其中的硬编码路径、内存任务状态和不安全文件操作。

## 2. 总体阶段

| 阶段 | 目标 | 依赖 |
| --- | --- | --- |
| P0 | 仓库骨架与公共契约 | 无 |
| P1 | 账号、权限与数据库基础 | P0 |
| P2 | Agent 管理与安全连接 | P1 |
| P3 | 构建模板、动态表单与项目 | P1，可与 P2 部分并行 |
| P4 | 数据库任务队列与 Rust 执行器 | P2、P3 |
| P5 | 实时日志、取消与产物 | P4 |
| P6 | 恢复、加固、打包部署与端到端验收 | P5 |

## 3. 任务清单

### P0：工程基础

#### T0.1 建立 Monorepo 骨架

**实施内容**

- 创建 `apps/web`、`apps/server`、`packages/contracts`、`agent`、`deploy`。
- Node 项目使用 pnpm workspace；统一 TypeScript、ESLint、Prettier 和 EditorConfig。
- Web 使用 Vue 3、TypeScript、Vite、Element Plus、Pinia、Vue Router。
- Server 使用 NestJS；Agent 初始化 Rust workspace。
- 增加根级 `lint`、`type-check`、`test`、`build` 命令和基础 CI。
- 增加环境变量示例和本地开发说明。

**验收标准**

- 全新环境按 README 可以安装依赖并启动 Web/Server。
- Web、Server、Agent 都能完成空项目构建。
- CI 能运行格式、静态检查和测试。

#### T0.2 定义公共业务契约

**实施内容**

- 在 `packages/contracts` 定义角色、Agent 状态、任务状态、表单字段和 API 错误码。
- 定义配置表单 JSON Schema 和运行时校验器。
- 定义 WebSocket 消息信封：`id`、`type`、`timestamp`、`payload`、`protocolVersion`。
- 定义任务状态转换表，Server 和测试共用。
- Rust 端建立对应 Serde DTO；用共享 JSON fixtures 做兼容测试。

**验收标准**

- 示例表单通过 Web/Server/Rust 三侧解析。
- 非法控件、重复 name、错误默认值和非法 options 均被拒绝。
- 协议 fixtures 在 TypeScript 和 Rust 测试中同时通过。

### P1：数据库、认证与授权

#### T1.1 PostgreSQL 与 Prisma 数据模型

**实施内容**

- 建立 User、RefreshToken、Agent、BuildTemplate、Project、BuildTask、Artifact、AuditLog 模型。
- 创建索引、外键、软删除字段和迁移。
- 对任务活动状态增加数据库级并发约束或事务锁方案。
- 增加开发种子数据与数据库测试工具。

**验收标准**

- 空数据库可一键迁移和初始化。
- 外键、唯一约束、软删除及分页查询测试通过。
- 两个并发领取请求不能为同一 Agent 建立两个活动任务。

#### T1.2 本地账号认证

**实施内容**

- 实现首个管理员初始化 CLI。
- 实现登录、刷新、退出、当前用户接口。
- 使用 Argon2id；Refresh Token 哈希存储并支持撤销。
- 管理员实现用户创建、禁用、重置密码。
- 增加登录限流、统一错误返回和安全 Cookie 配置。

**验收标准**

- 未登录请求被拒绝；禁用用户无法刷新会话。
- 重置密码后旧 Refresh Token 失效。
- 数据库和日志中不存在明文密码或令牌。

#### T1.3 RBAC 与资源所有权

**当前状态：已完成（权限基础设施）**

已完成集中式授权服务、显式资源元数据 Decorator、Project Ownership Guard，以及基于真实 PostgreSQL 的权限矩阵测试。当前阶段只提供后续业务 Controller 可复用的授权基础设施，不提前实现 Project、BuildTask、日志、Artifact 等正式业务接口。

**实施内容**

- 建立 Admin Guard 和 Project Ownership Guard。
- 将项目、任务、日志、产物权限沿项目 ownerId 统一校验。
- 管理员可访问所有资源；普通用户只能访问自己的资源。
- 越权资源对外统一返回 404 或既定安全错误，避免枚举。

**验收标准**

- 用户 A 无法通过 ID、列表过滤、下载地址访问用户 B 的任何资源。
- 管理员访问全部资源正常。
- 自动化权限矩阵测试覆盖所有受保护接口。

### P2：Agent 管理与连接

#### T2.1 Server Agent 管理模块


**当前状态：已完成（T2.1）**

已完成 Agent 管理 API、一次性注册令牌、审计、原生 WebSocket 连接、hello/heartbeat、单实例连接注册表和心跳超时。任务领取、执行、日志、产物及 Rust Agent 逻辑保留到后续阶段。
**实施内容**

- 管理员 Agent CRUD、启停、一次性令牌生成和轮换。
- 明文令牌只返回一次，数据库保存哈希。
- 管理页展示在线状态、主机、OS、架构、版本、最后心跳和当前任务。
- Agent 停用或令牌轮换后主动断开旧连接。

**验收标准**

- 无效、停用或已轮换令牌不能连接。
- Agent 元数据和在线状态正确更新。
- 非管理员不能查看令牌或管理 Agent。

#### T2.2 Rust Agent 连接骨架

**当前状态：已完成（T2.2）**

已完成 Rust Agent 配置加载、WSS/WebSocket 认证、hello/registered、心跳、指数退避重连、令牌吊销处理、结构化日志和优雅退出；任务领取与执行保留到后续阶段。
**实施内容**

- 实现配置文件/环境变量读取：Server URL、令牌、工作区根目录、日志级别。
- 实现 WSS 连接、认证、hello、15 秒心跳、指数退避重连。
- 上报 OS、架构、主机名和版本。
- 实现结构化本地日志和优雅退出。
- 提供 Windows、macOS、Linux 构建矩阵。

**验收标准**

- 三个平台编译通过。
- Server 重启后 Agent 自动重连。
- 令牌错误有明确诊断且不会高频重试。

### P3：构建模板、项目与动态表单

#### T3.1 构建模板后端


**当前状态：已完成（T3.1）**

已完成管理员构建模板 CRUD、启停、Agent 绑定、公共 formSchema 校验、普通用户启用模板读取和真实 PostgreSQL 集成测试；模板版本、Git 拉取、项目和任务执行保留到后续阶段。
**实施内容**

- 管理员实现构建模板 CRUD、启停和绑定 Agent。
- 字段包括 Git URL、单条命令、产物目录、表单 JSON、超时。
- 使用公共 Schema 校验表单。
- 对产物相对路径和所有字符串做安全校验。
- 不实现模板版本、Git 拉取或快照。

**验收标准**

- 非管理员不能修改模板。
- 非法路径、重复字段、未知控件和已停用 Agent 绑定被拒绝。
- 更新模板后读取接口立即返回当前内容。

#### T3.2 构建模板管理页面


**当前状态：已完成（T3.2）**

已完成最小登录/会话恢复、管理员路由守卫、Agent 管理、构建模板管理和 formSchema 本地编辑/公共契约校验/安全预览。开发环境 CSRF Cookie 使用 Path=/ 供管理页面读取，Refresh Cookie 仍保持 HttpOnly 和受限 Path=/api/auth。T3.3 项目后端已完成，项目页面由 T3.4 提供。
**实施内容**

- Agent、模板列表及创建编辑页面。
- JSON 上传、文本预览、格式化、错误定位和动态表单预览。
- Agent 离线/停用状态提示。
- 删除和停用操作二次确认。

**验收标准**

- 管理员可从上传 JSON 到预览、保存完整走通。
- 非法 JSON 和协议错误能定位到具体字段。
- 普通用户不显示且不能访问管理路由。

#### T3.3 项目后端与所有权

**当前状态：已完成（T3.3）**

已完成项目创建、分页列表、详情、字段更新、专用配置保存和软删除；所有接口复用 Project.ownerId 所有权 scope 与显式 OwnershipGuard。新增公共配置值校验/规范化/兼容性分析，模板变更、默认值、过期字段和构建可用性均有真实 PostgreSQL API 集成测试。T3.4 Web 项目页面已完成。

**实施内容**

- 项目 CRUD、软删除、分页与名称搜索。
- 创建时绑定已启用模板并手填分支。
- 项目配置独立保存；使用模板当前 Schema 校验和过滤。
- 模板变化后计算缺失、过期、类型冲突字段；不合法项目禁止构建。
- 普通用户查询自动限定 ownerId。

**验收标准**

- 一个项目只有一份配置。
- 用户之间严格隔离。
- 模板增加、删除和改变字段类型的兼容测试通过。

#### T3.4 动态表单与项目页面

**当前状态：已完成（T3.4）**

已完成登录用户项目列表、创建、基本信息编辑、配置编辑/保存、详情、兼容性状态和软删除页面；动态控件仅按白名单显式渲染，构建任务入口保留给 T4.1。

**实施内容**

- 实现控件白名单渲染器，不使用动态任意组件。
- 支持 input、textarea、number、select、radio、checkbox、switch、date、password。
- 实现默认值、必填、范围、长度、pattern 和 options 校验。
- 项目列表、创建、编辑、配置保存和详情；构建任务入口保留给 T4.1。
- 普通用户只能看到自己的项目。

**验收标准**

- 示例 Schema 可以正确渲染并保存预期 JSON 对象。
- 刷新后配置回填正确。
- 前后端校验结果一致；绕过前端提交非法值仍被 Server 拒绝。

### P4：任务队列与 Agent 执行

#### T4.1 Server 任务创建与队列

**当前状态：已完成（T4.1）**

**实施内容**

- 实现创建任务、任务列表、详情和状态历史。
- 创建时复制项目当前配置，不复制模板。
- Agent 离线进入 WAITING_AGENT，在线进入 QUEUED。
- 使用数据库事务实现按 Agent、创建时间领取；每个 Agent 最多一个活动任务。
- 建立租约令牌、幂等 claim 和派发超时回收。
- 增加 `BuildTaskStatusHistory` 状态历史表；任务创建、排队、派发、确认和超时回收均在数据库事务中记录。
- 增加 `/api/projects/:projectId/tasks` 创建/列表接口和 `/api/tasks/:taskId` 详情接口，复用 Project 所有权 scope。
- Agent hello/disconnect、`task.available`、`task.claim`、`task.assignment`、`task.accepted` 已接入现有原生 WebSocket。

**验收标准**

- 同 Agent 串行、不同 Agent 并行。
- 并发 claim 不会重复派发。
- Server 重启后排队任务继续存在并可领取。
- PostgreSQL 集成测试覆盖所有权、配置快照、状态历史、并发 claim、租约校验、超时回收和重启后的数据库队列语义。

#### T4.2 Rust Agent 工作区与 Git 执行

**实施内容**

- 安全创建 `<workspace>/tasks/<taskId>/source`。
- 检查工作区权限、磁盘空间和系统 Git。
- 使用系统 Git 和参数数组 Clone 指定 URL/分支。
- 获取并回传 Commit SHA。
- 防止工作区路径逃逸和危险清理目标。

**验收标准**

- 公有测试仓库可在三平台正常拉取指定分支。
- 不存在分支、无权限、磁盘不足和 Git 缺失均返回结构化失败原因。
- 清理逻辑不能删除工作区之外的文件。

#### T4.3 Rust Agent 配置与命令执行

**实施内容**

- 根据任务参数生成格式化 `platform.config.json`，临时文件后原子替换。
- Windows 使用 `cmd.exe /D /S /C`，Unix 使用 `/bin/sh -lc`；记录具体 Shell。
- 捕获 stdout/stderr、退出码和超时。
- 用户配置不得插入命令字符串。
- 实现任务生命周期上报。

**验收标准**

- 构建进程能读取正确配置文件。
- stdout/stderr 均实时输出且非 UTF-8 内容不会使 Agent 崩溃。
- 非零退出和超时正确进入 FAILED。

### P5：日志、取消与产物

#### T5.1 实时与历史日志

**实施内容**

- Agent 日志分块、序号、短暂磁盘缓冲和断线续传。
- Server 幂等追加任务日志文件并更新偏移。
- WebSocket 向有权限的浏览器广播。
- HTTP 支持按 offset/limit 读取历史；页面刷新后续接。
- 对敏感配置值做服务端和 Agent 双重遮蔽。

**验收标准**

- 日志块乱序、重复和短暂断线不会造成明显重复或丢失。
- 用户不能订阅其他用户任务日志。
- 大日志不会整体加载进数据库或浏览器内存。

#### T5.2 跨平台取消与超时

**实施内容**

- 排队任务直接取消；运行任务发送幂等取消通知。
- Rust Agent 实现 Windows Job Object、Unix 进程组的进程树终止。
- 先优雅终止，超时后强制终止。
- 取消和自然结束竞争时使用状态机裁决。

**验收标准**

- 测试父进程和子进程均被终止。
- 重复取消不报错，不会取消后续任务。
- 取消完成后工作区被安全清理。

#### T5.3 产物收集与上传

**实施内容**

- 命令成功后递归扫描 artifactDir，拒绝符号链接逃逸。
- 生成 relativePath、size、SHA-256 清单。
- Server 提供租约认证的流式上传、幂等确认和 2 GB 总量限制。
- 文件落盘采用临时文件、Hash 校验后原子移动。
- 实现产物列表、授权下载、软删除和按任务打包下载。
- 空产物目录或任一文件上传失败时任务失败。

**验收标准**

- 多层目录、同名不同路径和大文件上传正确。
- 路径穿越、Hash 不一致、超限和越权下载被拒绝。
- 任务只有在所有产物确认后进入 SUCCEEDED。

#### T5.4 任务详情页面

**实施内容**

- 任务列表、状态筛选、详情、状态时间线、实时日志、产物列表。
- 支持取消、停止、重新构建、单文件及整包下载。
- 展示模板、项目、分支、Commit SHA、Agent、命令退出码和失败原因。
- 处理 Agent 离线、等待、失联和重连状态。

**验收标准**

- 核心任务状态都有明确页面反馈。
- 刷新页面后任务状态、历史日志和产物不丢失。
- 所有操作遵循项目所有权。

### P6：恢复、安全、部署和验收

#### T6.1 断线恢复与幂等性

**实施内容**

- Agent 重连上报当前 taskId、租约和最后日志序号。
- Server/Agent 重启后的任务对账。
- AGENT_LOST、5 分钟恢复窗口和超时失败。
- Agent 在终态确认后清理；启动时安全清理已确认终态的残留目录。
- 为任务创建、claim、状态、日志、上传、完成和取消增加幂等测试。

**验收标准**

- 在准备、运行和上传阶段分别模拟断线/重启，不重复执行命令。
- 无法恢复的任务得到明确失败原因，不长期卡住。
- 不产生孤立活动任务或未关联产物。

#### T6.2 安全加固与审计

**实施内容**

- HTTPS/WSS、CORS、Helmet、CSRF/Cookie 策略、限流和请求大小限制。
- 敏感字段加密、遮蔽和密钥配置。
- 登录、用户/Agent/模板变更、取消任务、删除产物审计。
- 路径、上传、命令边界和权限渗透测试。
- 依赖漏洞扫描和秘密扫描。

**验收标准**

- 安全测试覆盖文档中列出的越权、路径穿越、令牌泄漏和上传攻击。
- 审计记录包含操作者、动作、资源、时间和结果，但不包含明文秘密。

#### T6.3 部署、Agent 安装与运维

**实施内容**

- Docker Compose 提供 Server、Web、PostgreSQL 和持久化存储。
- 增加数据库迁移、备份恢复、日志轮转和磁盘容量说明。
- Server 增加 liveness/readiness。
- Rust Agent 产出 Windows、macOS、Linux 发布包和 SHA-256。
- 提供 Windows Service、launchd、systemd 安装模板。
- 编写管理员手册、Agent 安装手册和故障排查文档。

**验收标准**

- 一台新服务器可按文档完成部署和升级。
- 三类系统 Agent 可安装为后台服务并自动启动。
- 数据库和产物备份可以恢复到新环境。

#### T6.4 端到端验收与发布门禁

**实施内容**

- 建立模拟 Git 仓库和跨平台测试构建命令。
- 自动覆盖登录、模板、项目、排队、离线恢复、日志、取消、产物及权限。
- 执行产品设计第 13 节全部验收场景。
- 建立发布检查表、已知限制和回滚步骤。

**验收标准**

- 所有关键 E2E 场景通过。
- Web/Server/Agent 构建产物可重复生成。
- 无 P0/P1 缺陷后才允许标记第一版完成。

## 4. 推荐的智能体分工

在依赖满足后，可按模块分配长期负责人：

| 智能体 | 主要责任 |
| --- | --- |
| A：架构与契约 | T0.1、T0.2，维护跨语言协议与状态机 |
| B：Server | T1.1～T1.3、T2.1、T3.1、T3.3、T4.1 |
| C：Web | T3.2、T3.4、T5.4 |
| D：Rust Agent | T2.2、T4.2、T4.3、T5.2 |
| E：日志与产物 | T5.1、T5.3，与 Server/Agent 负责人协作 |
| F：质量与部署 | T6.1～T6.4，从 P1 起持续补充测试 |

若并发智能体较少，优先保持 Server 与 Agent 两条主线，Web 在 API 稳定后跟进。跨模块协议只能由契约负责人修改；其他智能体先提交契约变更提议，避免各自定义不兼容消息。

## 5. 建议实施顺序与里程碑

### M1：可登录的管理骨架

完成 T0.1～T1.3。结果：本地账号、RBAC、数据库和空管理台可用。

### M2：模板、项目和在线 Agent

完成 T2.1～T3.4。结果：管理员配置 Agent/模板，用户创建自己的项目并保存动态配置。

### M3：最小可用构建闭环

完成 T4.1～T4.3 和 T5.3 的基础上传。结果：Agent 能领取任务、Clone、写配置、运行命令和上传产物。

### M4：可用产品体验

完成 T5.1～T5.4。结果：可靠日志、取消、任务详情和产物下载完整可用。

### M5：可部署第一版

完成 T6.1～T6.4。结果：跨平台安装、恢复、安全、运维和 E2E 达到发布门槛。

## 6. 每个智能体任务的统一交付格式

每个任务完成时必须提交：

1. 实现摘要和明确未实现项。
2. 修改文件列表。
3. 数据模型、环境变量、API 或协议变化。
4. 执行过的测试命令和结果。
5. 手工验收步骤。
6. 安全与兼容性风险。
7. 后续任务需要知道的接口约束。

禁止仅以“页面能打开”或“命令能运行”作为完成依据；必须满足对应任务的验收标准和自动化测试。
